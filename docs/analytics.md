# アクセス解析（GA4）と Search Console の引き継ぎ

旧サイト（WordPress）で使っている GA4 と Search Console を、新サイトでもそのまま使い続けるための設定と手順です。
ドメイン（`https://www.kantanfund.net/`）も記事の URL も変わらないので、**GA4 のプロパティも Search Console のプロパティも作り直しません**。Search Console の「アドレス変更ツール」も使いません（ドメインを変えるときのためのもの）。

Google の画面での操作はご自身で行ってください。画面の表記は変わることがあります。

## 旧サイトの状況（2026-10-25 に公開ページから確認）

- 旧サイトには **Site Kit by Google**（WordPress のプラグイン、1.188.0）が入っている。GA4 のタグは Site Kit が入れていると考えられる。
- GA4 の測定ID は `G-1BD1TYK7XG`（2026-10-25 に先方から。新サイトにも入れ済み）。
- Search Console の所有権の確認は **HTML ファイル**（`googlebd1b967076c9ab2f.html`。2026-10-25 に先方から）。新サイトにも同じファイルを置き済み（下の「確認用ファイルの配信」）。
- （参考）Site Kit で Search Console をつなぐと、Site Kit が入れた **HTML タグ** で確認していることもある。その場合に備えて、タグを出す仕組み（`ANALYTICS.googleSiteVerification`）も用意している（いまは空）。

## 新サイトの作り（コード）

| 内容 | 場所 |
|---|---|
| GA4 のタグ（gtag.js） | `src/layouts/Layout.astro`。測定ID は `src/constants/index.ts` の `ANALYTICS.ga4MeasurementId` |
| Search Console の確認用 HTML タグ | 同じく `Layout.astro`。値は `ANALYTICS.googleSiteVerification`（空のあいだは出さない） |
| Search Console の確認用ファイル | `public/googlebd1b967076c9ab2f.html`（旧サイトと同じファイル）と、`data/redirects.csv` の 200 の行（下の「確認用ファイルの配信」） |
| サイトマップ | `/sitemap.xml`（[site.md](site.md) の「サイトマップ」） |
| robots.txt | `/robots.txt`。本番ではサイトマップの場所を書く |
| 公開日の確認スクリプト | `npm run check:launch`（下の「4. 公開日の確認」） |

- GA4 は、**本番のドメイン（`www.kantanfund.net`）で開いたときだけ**計測する。手元の確認・`*.workers.dev`・プレビューのアクセスは GA4 に送らない。
- 測定ID を空にすると、どこで開いても計測しない。
- 記事一覧のカテゴリのチップを押すと URL（`?category=`）が変わる。GA4 の拡張計測機能の「ブラウザの履歴イベントに基づくページの変更」がオンなら、これも1ページビューとして数えられる（絞り込みの使われ方が分かるので、そのままにしている）。

### 確認用ファイルの配信

Cloudflare の静的ファイルの配信は、`/xxx.html` で開くと `/xxx` へ 307 で転送する（URL から `.html` を外す動き）。
確認用ファイルが転送されると Search Console の確認に失敗するおそれがあるため、`data/redirects.csv` に `/googlebd1b967076c9ab2f.html` → `/googlebd1b967076c9ab2f` の **200**（転送せずに中身を返す）の行を入れている。
手元の `wrangler dev` で、`/googlebd1b967076c9ab2f.html` が転送されずに 200 でファイルの中身を返すことを確かめた（2026-10-25）。`npm run check:launch` でも確かめる。

確認用ファイルを差し替えるときは、`public/` のファイルと CSV の行の両方を直し、`npm run redirects` を実行する。

## 1. 旧サイトで確かめること（済み: 測定ID・確認方法とも 2026-10-25 に確認）

### GA4 の測定ID

1. [Google アナリティクス](https://analytics.google.com/) を開き、かんたんファンドのプロパティを選ぶ。
2. 左下の **管理（歯車）** → **データの収集と修正** → **データストリーム** → ウェブのストリームを開く。
3. **ストリームの URL** が `https://www.kantanfund.net` であることと、**測定 ID**（`G-` で始まる）を控える。
4. 同じ画面の **拡張計測機能** がオンかどうかも見ておく（オンのままでよい）。

測定ID は、ページの HTML に載る公開の値なので、チャットに貼って大丈夫です。

WordPress の管理画面からも確かめられます: **Site Kit → 設定 → 接続されたサービス → アナリティクス**。
ここに **Google タグ マネージャー**（`GTM-` で始まる ID）もつながっていたら教えてください（その場合はタグ マネージャーのコンテナを新サイトに入れるかを決めます）。

### Search Console のプロパティと確認方法

1. [Search Console](https://search.google.com/search-console) を開き、左上のプロパティの一覧を見る。
   - `https://www.kantanfund.net/` のような URL → **URL プレフィックス**のプロパティ
   - `kantanfund.net`（`https://` が付かない）→ **ドメイン**のプロパティ（DNS で確認している）
2. そのプロパティで **設定** → **所有権の確認** を開き、「確認方法」に出ているものを控える（複数あることもある）。
3. **設定** → **ユーザーと権限** で、ご自身が「オーナー」になっていることを確かめる。

## 2. 確認方法ごとの対応（公開日より前に済ませる）

| 旧サイトの確認方法 | 新サイトでの対応 |
|---|---|
| **HTML タグ**（Site Kit が入れたもの） | **所有権の確認** → **HTML タグ** に出る `<meta name="google-site-verification" content="……">` の `content` の値を教えてください。`ANALYTICS.googleSiteVerification` に入れます（タグは公開の値なのでチャットに貼って大丈夫です）。 |
| **HTML ファイル** | **所有権の確認** → **HTML ファイル** から `google……html` をダウンロードして渡してください（同じユーザー・同じサイトなら、何度ダウンロードしても同じファイル）。`public/` にそのまま置きます。 |
| **Google アナリティクス** | 新サイトにも同じ測定ID のタグが入るので、そのまま通る（GA4 のプロパティの「編集者」以上の権限が要る）。 |
| **Google タグ マネージャー** | 新サイトにタグ マネージャーを入れないなら、下の DNS での確認を足す。 |
| **DNS レコード** / **ドメイン名プロバイダ** | DNS を Cloudflare に移すときに、`google-site-verification=……` の TXT レコードを必ず写す（[cloudflare.md](cloudflare.md) の5）。 |

**どの方法でも、DNS（TXT レコード）での確認を1つ足しておくことをおすすめします。**
サイトの作りに左右されず、今後サイトを作り直しても確認が外れません。

- DNS を Cloudflare に移した後（公開日より前）、Search Console の **所有権の確認** → **その他の確認方法** → **ドメイン名プロバイダ** で TXT レコードの値を出し、Cloudflare の DNS に TXT レコード（名前 `@`）として追加して **確認** を押す。
- 余裕があれば、**ドメイン**のプロパティ（`kantanfund.net`）も追加する（同じ TXT レコードで確認できる）。www なし・http も含めて1つのプロパティで見られる。過去のデータも表示される。

## 3. GA4 の設定（公開日より前でも後でもよい）

必須ではありませんが、作り直しの前後を比べやすくするための設定です。

1. **データ保持期間を 14 か月にする**: 管理 → **データの収集と修正** → **データ保持** → 「イベントデータの保持」を **14 か月**。標準の2か月のままだと、探索レポートで公開前後を比べられなくなる。
2. **お問い合わせの送信をキーイベントにする**（送信数を数えたい場合）: 管理 → **データの表示** → **イベント** → **イベントを作成** → 名前 `contact_submit`、条件は `event_name` が `page_view` かつ `page_location` に `/contact/thanks/` を含む。保存後、**キーイベント** の一覧で `contact_submit` をキーイベントにする。
3. **Search Console とのリンクを確かめる**: 管理 → **サービス間のリンク設定** → **Search Console のリンク**。旧サイトでつないでいればそのまま使える（プロパティが変わらないため）。
4. **公開日に注釈を残す**: レポートのグラフで **注釈を追加** し、「新サイトに切り替え」と書く（公開後の数字の変化の理由が後から分かる）。

Site Kit の連携は、公開日まで外さないでください（旧サイトの計測と所有権の確認が止まるため）。新サイトに切り替われば WordPress は表示されなくなるので、Site Kit の設定の削除は不要です。

## 4. 公開日の確認

切り替え（[cloudflare.md](cloudflare.md) の6）が済んだら、上から順に確かめます。

### GA4

1. 新サイトをスマホと PC で開き、GA4 の **レポート** → **リアルタイム** に自分のアクセスが出ることを確かめる。
2. ブラウザで **ページのソースを表示** し、`googletagmanager.com/gtag/js?id=G-……` が読み込まれていること（開発者ツールの「ネットワーク」で `collect` へのリクエストが出ていること）を確かめる。
3. `https://kantan-fund.<アカウント名>.workers.dev/` で開いたときは、`collect` へのリクエストが出ないことを確かめる。

### Search Console

1. **設定** → **所有権の確認** で、確認が通っている（「確認済み」）ことを確かめる。
2. **サイトマップ** で `https://www.kantanfund.net/sitemap.xml` を送信する。旧サイトで送っていた `sitemap_index.xml` などは新サイトでは `/sitemap.xml` に転送されるので、一覧から削除してよい（送ったままでもエラーにはならない）。
3. **URL 検査** で TOP・ハブページ1つ・記事2〜3本を調べ、**公開 URL をテスト** で「URL は Google に登録できます」と出ることを確かめる。出たら **インデックス登録をリクエスト** を押す（TOP とハブページだけでよい）。
4. **設定** → **robots.txt** で、新しい robots.txt が取得されている（`Disallow: /` でない）ことを確かめる。

### 転送とサイトマップ（コマンド）

手元で次を実行すると、`data/redirects.csv` の転送がすべて 301 で正しい転送先に行くか、サイトマップの URL がすべて 200 で開けて noindex が付いていないかを確かめられます。問題があると `NG` の行が出ます。

```sh
npm run check:launch
```

- www なし（`https://kantanfund.net/`）と `http://` の転送も確かめる（Cloudflare 側の設定）。
- 公開前に workers.dev で確かめるときは `npm run check:launch -- https://kantan-fund.<アカウント名>.workers.dev`（www なし・http の転送と noindex は確かめない）。
- `/?p={記事ID}` の転送は、対応表ができてから確かめる対象に足す（[redirects.md](redirects.md)）。

## 5. 公開後に見ること

| いつ | どこで | 見ること |
|---|---|---|
| 翌日 | Search Console → **サイトマップ** | 送信したサイトマップが「成功しました」になり、検出された URL の数が記事数＋固定ページの数と合う |
| 翌日〜1週間 | GA4 → **リアルタイム**・**レポート** → **エンゲージメント** → **ページとスクリーン** | 前の週と比べてページビューが極端に減っていない。ページタイトル「ページが見つかりません」が多くない（多ければ、転送の漏れがある URL を [redirects.md](redirects.md) の手順で足す） |
| 1〜4週間 | Search Console → **ページ**（インデックス作成） | 「見つかりませんでした（404）」が増えていない。「リダイレクトがあります」が増えるのは転送した旧 URL なので問題ない |
| 1〜4週間 | Search Console → **検索パフォーマンス** | 公開前の4週間と比べて、表示回数・クリック数が大きく落ちていない（切り替え直後に少し上下するのは普通） |
| 1か月後 | Search Console → **ウェブに関する主な指標** | 「不良」の URL がない |
