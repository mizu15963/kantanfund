# お問い合わせフォーム

参考プロジェクト（クラファンセレクトの `/contact`）と同じ作りです。フォームの送信は、このサイトの Worker が受け取って microCMS に保存します（書き込み用のキーをブラウザに出さないため）。

| ファイル | URL | 作り方 |
|---|---|---|
| `src/pages/contact/index.astro` | `/contact/` | **アクセス時**（サイトで唯一）。送信もこのページが受け取る |
| `src/pages/contact/thanks.astro` | `/contact/thanks/` | ビルド時。送信完了（noindex・サイトマップに載せない） |
| `src/libs/contact.ts` | — | 入力のチェック、Turnstile の確認、microCMS への保存（サーバー側だけで使う） |

- 旧サイトの `/support/`（Google フォームへの案内のページ）は `/contact/` へ 301 で転送する（[redirects.md](redirects.md)）。
- 見た目は運営者情報・プライバシーポリシーと同じく、`Layout` の `plain`（PC 幅の左右を出さない）。

## 導線

- フッターの「サイトについて」、運営者情報の表の「お問い合わせ」、プライバシーポリシーの「お問い合わせ窓口」。

## 入力項目

項目名・選択肢は `schema/contacts.json` から読み込む（CLAUDE.md の「API の項目定義」）。選択肢を変えるときは、microCMS の項目を直してスキーマを書き出し、`schema/contacts.json` を上書きする（コードは直さなくてよい）。

| 項目 | フィールドID | 種類 | 必須 | 上限 |
|---|---|---|---|---|
| お名前（ニックネーム可） | `name` | テキスト | ○ | 50文字 |
| メールアドレス | `email` | テキスト（形式もチェック） | ○ | 254文字 |
| お問い合わせ種別 | `category` | セレクト（記事について／掲載・広告について／個人情報の取り扱いについて／その他）。画面はラジオボタン | ○ | — |
| お問い合わせ内容 | `message` | テキストエリア | ○ | 3000文字 |
| プライバシーポリシーへの同意 | — | チェックボックス（保存しない） | ○ | — |

- 文字数の上限は `src/constants/index.ts` の `CONTACT.maxLength`。
- 「個人情報の取り扱いについて」は、プライバシーポリシーで開示・削除などの請求をこのフォームで受けるために足した。

## 送信の流れ

1. 入力のチェック（サーバー側）。問題があれば、入力内容を残したまま項目ごとにエラーを表示する（ステータス 400）。
2. 自動送信よけ
   - **Cloudflare Turnstile**: 送信前に自動で確認する（多くの場合は操作不要）。360px 未満の画面では小さい表示（compact）にする。
   - **見えない入力欄**（`website`）: 値が入っていたら自動送信とみなし、保存せずに完了ページへ移動する。
3. microCMS の `contacts` API に**下書き**で保存する（`CONTACT.endpoint`）。下書きなのでサイトに公開されることはない。
4. 成功したら `/contact/thanks/` へ移動する。Turnstile の確認や保存に失敗したら「送信に失敗しました」と表示し、エラーを Workers のログに出す（`[contact]`）。

## 送信ボタン

- 必須項目の入力、メールアドレスの形式、同意のチェック、Turnstile の確認がそろうまで、送信ボタンを押せないようにする（グレー表示と案内文）。
- メールアドレスの形式が正しくないときは、入力欄から離れた時点でエラーを出す（入力の途中では出さない）。形式の決まりは `CONTACT.emailPattern`（サーバー側と画面側で同じもの）。
- 押したらすぐに押せなくし、「送信中…」と表示する（二重送信の防止）。
- これは使う人のための補助（JavaScript）。**不正な送信や連打の防止はサーバー側**（入力のチェックと、1回しか使えない Turnstile の証明）で行う。さらに制限が必要なら、Cloudflare のレート制限（`/contact/` への POST の回数制限）を足す。

## 表示の切り替え

- Worker の実行時の変数（下の表の4つ）がそろっていない間は、フォームの代わりに「現在準備中です」と表示する（送信されても保存しない）。

## 設定の手順

キーはチャットやリポジトリに書かず、Cloudflare の画面と手元の `.dev.vars` にだけ入れてください。

1. **microCMS**: `contacts` API を作る（[microcms.md](microcms.md) の「API の作り方」。`schema/contacts.json` をインポート）。
2. **microCMS**: 今の API キー（`MICROCMS_API_KEY`）の権限に、`contacts` の **POST だけ**を足す（GET は付けない。キーが漏れても、お問い合わせの個人情報を読み出されないように）。
3. **microCMS**: `contacts` の **API 設定 → Webhook → メール通知** で、届いたときに知らせるメールアドレスを登録する（デプロイフックは登録しない。お問い合わせのたびに再ビルドされるため）。
4. **Cloudflare**: ダッシュボード → **Turnstile** → **ウィジェットを追加**。ホスト名に `www.kantanfund.net` と `kantan-fund.<アカウント名>.workers.dev` を入れ、モードは「管理（Managed）」。サイトキーとシークレットキーができる。
5. **Cloudflare**: Worker `kantan-fund` の **設定（Settings）→ 変数とシークレット（Variables and Secrets）**（ビルド用ではなく実行時のほう）に、種類「シークレット」で次の4つを入れる。

| 名前 | 内容 |
|---|---|
| `MICROCMS_SERVICE_DOMAIN` | ビルド用と同じ値 |
| `MICROCMS_API_KEY` | ビルド用と同じキー（2で `contacts` の POST を足したもの） |
| `TURNSTILE_SITE_KEY` | Turnstile のサイトキー（公開される値だが、実行時に読むためシークレットとして登録する） |
| `TURNSTILE_SECRET_KEY` | Turnstile のシークレットキー |

6. `/contact/` を開いてテスト送信し、microCMS の `contacts` に下書きで入ること、通知メールが届くことを確かめる。

- 手元で試すときは、`.dev.vars` に4つを書いて `npx wrangler dev -c dist/server/wrangler.json` で開く。Turnstile は Cloudflare が公開しているテスト用のキー（サイトキー `1x00000000000000000000AA`、シークレットキー `1x0000000000000000000000000000000AA`。必ず確認が通る）を使える。

## 決まっていないこと

- 通知メールの宛先（3で登録するアドレス）
- 返信の運用（誰がどのアドレスから返信するか）
- 自動返信メール（送った人への受付確認）を送るか（送る場合はメール送信の仕組みが別に必要）
